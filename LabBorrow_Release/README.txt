一、本次升级说明（第三版相对第二版）
----------------------------------------------------------------
新增两项防止误刷与刷数据的功能，另加四项实用功能：

  【必需】1. 刷卡距离限制 —— 防止把隔壁货架、整箱设备一起误读进来
            · 硬件侧：通过 SDK 的 SetPowerDbm 把读卡器射频功率从出厂最大值
              降到指定 dBm（界面提供 15/18/22/26/30 dBm 五档，也可自填），
              UHF 读卡距离与功率近似成正比，降功率就是物理意义上的“限距”。
            · 软件侧：连续命中确认 —— 标签必须在连续若干轮盘点中都被读到
              （默认 2 轮，允许漏 1 轮）才算一次有效刷卡。只被零星读到一两次的
              标签（正是“距离边缘的偶发误读”）一律判为「距离未确认」，只在
              事件列表提示，不产生任何借还记录。
            · 边沿触发：同一标签在上报后必须离开天线范围才能再次上报，彻底
              解决“标签一直放在读卡器上被反复触发”“借出后立即自动归还”。
            ※ 本型号 SDK 没有 RSSI 接口，因此距离控制采用“功率 + 命中确认”
              两个手段配合，而不是读信号强度（详见第十四节设计说明）。

  【必需】2. 刷卡间隔时限 —— 防止恶意刷数据
            四层规则，全部可在界面调整、立即生效：
            · 全局最小间隔：任意两次成功登记之间的最小时间差（默认 800 ms）；
            · 借出→归还最短间隔（默认 10 秒）：防止“借出立即归还”造出 0 分钟假记录；
            · 归还→借出最短间隔（默认 30 秒，随包库为 60 秒，见第六节）；
            · 异常刷卡锁定：60 秒窗口内同一标签刷卡超过 8 次（或全局超过 40 次）
              即临时锁定该标签 120 秒，锁定期间的刷卡一律拦截。
            被拦截的刷卡不写借还流水，但全部记入新增的 audit_log（刷卡审计）表，
            可在「系统设置」页查看，作为追责证据。
            ※ 旧版本 README 里提到的 settings.min_interval_min 实际上从未被代码
              读取（去抖间隔被写死成 350 ms），本版已修正并做了兼容迁移。

  3. 在借明细 + 逾期高亮：首页「在借看板」从只显示数量升级为明细表
     （设备 / 借用人 / 已借时长 / 期限状态），逾期红色、临期黄色。
  4. 借用期限与逾期提醒：可设默认借用天数（默认 7 天）与临期提前量（默认 24 小时），
     借出时自动写入应还时间；流水表新增「应还时间」列，逾期未还显示为红色。
  5. 借用人卡（学生卡）双卡模式：新增 users 表与「用户管理」页。
     开启双卡模式后：先刷学生卡 → 再刷设备卡 → 自动完成借出，不用手工输入姓名；
     未开启时，刷学生卡也会自动填入借出对话框的借用人。
  6. 统计报表页：区间指标 + 借出/归还趋势 + 设备借出排行 + 借用人排行 + 分类占比
     （全部用 GDI+ 手绘，不依赖第三方组件），支持导出 CSV。
  6.1 切换页面不卡顿：页面数据只在「首次打开」或「数据有变动」时重新取数，
     取数还安排在切换动画结束之后，不会和动画抢主线程。
     系统设置页把不常用的分区（③借用期限 / ④借用人卡 / ⑤备份恢复 / ⑥刷卡审计）
     默认收起，收起的控件不参与布局，点分区标题即可展开/收起。
     连续快速点导航也不会串页：每次切换都会先停掉上一场还没播完的切换动画。
     实测二次切换耗时：主控台/设备/记录/用户 ≈ 25ms，统计报表 ≈ 75ms，
     系统设置 ≈ 210ms（优化前系统设置约 480ms）。
  6.2 小窗口体检：冒烟测试会自动把窗口缩到 1080x654（普通笔记本大小），
     检查主控台顶部卡片有没有控件重叠/内容溢出。主控台卡片内部的行高
     已改为按字号固定（不再依赖窗口尺寸重算），任何窗口大小下行距都一致。
  6.3 高分屏适配：2560x1600 等屏通常开了 150% 缩放，界面字体会被系统放大，
     固定像素的行高会把文字裁掉一半。主控台卡片与统计指标卡的行高现已全部
     改为按字体实测高度（Font.Height 随 DPI 自动缩放），大屏小屏都不裁字。
  6.4 拖动窗口不卡不闪：改窗口尺寸时的重排做了三件事——
     节流（拖动时最多每 100ms 重排一次，不再每一像素算一遍）、
     防重入（改行高不会再反向触发布局抖动）、切页动画收短（40 帧→18 帧，
     重页面每帧全页重绘的代价大幅下降）。
     冒烟测试新增「缩放体检」：自动在 5 种窗口尺寸间来回切换，
     验证无卡顿、内容不被挤出（当前实测最慢约 90ms，远低于可感知阈值）。
  6.5 【重要】音乐文件放不出来的真正原因与判据
      程序解压在「桌面」时，Windows 会给它打上「低完整性(Low)」标签。
      这种状态下：MCI 打不开文件（错误码 0x10A / 0x115），Windows Media Player
      虽然能创建、但会一直停在过渡状态(playState=9)永远不真正出声
      ——表现为「点了试听/演示，界面显示已播放，但一点声音都没有」。
      判据很简单：数据库同时是只读的（顶部红色提示条 / Db.Writable=False）。
      处理：运行一次 fix_integrity.bat（启动时会弹窗引导，可一键打开），
      跑完后关闭并重新打开程序，音乐文件即可正常播放。
      程序侧已改为：只有播放器真正进入播放状态才认为成功，否则回退内置合成音，
      并在「实时事件」列表里写清失败原因和修复办法，不会再出现"假成功"。
  6.6 音效播放的最终方案（本机实测，按可靠性排序）
      实测结果：MCI 在本机一律失败（错误码 0x115，换成纯英文路径同样失败 → 与路径无关）；
      WMP12(WMPlayer.OCX) 能创建但永远停在过渡状态(playState=9)不出声；
      DirectShow 组件不存在；【WMP6.4(MediaPlayer.MediaPlayer.1，进程内 COM) 真正播放成功】。
      因此播放顺序改为：WMP6.4 → MCI → WMP12 → 内置合成音，并且每一环都只把
      "播放器真正进入播放"当作成功，不再假报成功。
  6.7 【最省事】把音频放到软件根目录即可，不用配数据库
      程序目录（或其中的 sounds 文件夹）里放音频文件就会被自动识别并使用：
        程序根目录 或 根目录\sounds\  ← 放这里就行
      文件名建议带关键字：异常/锁定/man/abuse → 异常音效；借出/borrow → 借出；
      归还/return → 归还；拦截/blocked → 拦截。
      若目录里只有一个音频文件，不管叫什么名字都会直接拿来用。
      好处：数据库只读（没跑 fix_integrity.bat）时设置存不进去，但音效照样能用。
      已随程序附带 sounds\sfx_abuse.mp3（异常音效，已验证可正常播放）。
      设置页 ⑦ 区新增「打开音效文件夹…」按钮，一键打开该目录。
  6.8 设置页的保存体验（防止"改了却不生效"的误会）
      ● 设置页最顶部也放了一个「保存设置（立即生效）」按钮（原来只在最底部）；
      ● 顶部有一行状态：改了任何参数会立即变成「● 有未保存的修改」，
        保存后回到「所有修改均已保存」——改没改、存没存一目了然；
      ● 直接关闭程序时若还有没保存的修改，会先问你要不要存；
      ● 冒烟测试新增「设置项体检」：26 个设置项逐个"改值→保存→重载"验证全部生效；
        另有「分区体检」确认每个分区展开后内容完整。
  6.9 拖动窗口边框时不再重排（防卡顿的最终方案）
      拖动过程中一次布局都不算（冒烟测试验证重排次数为 0），松手才按最终尺寸
      统一算一次（实测约 20ms）。卡片圆角路径也做了缓存，重绘更省。
  6.10 界面字号可调（老师改进 #4）
      系统设置 → ⑧ 界面字号：紧凑 / 标准 / 大 / 超大 四档，全界面一起缩放，
      另有「触屏友好」开关。切换字号会自动重启一次程序（字号在建界面时生效）。
      高分屏、投影远看、视力不好的同学都能调到合适的字。
  6.11 归还到期提醒 —— 提醒对象是「借用设备的同学本人」（老师改进 #1）
      核心问题：提醒必须对到人，而不是只给管理者看一眼。所以做了四条触达路径：
      ① 借出当场：借出对话框里就写明「本次应归还：MM-DD HH:MM」，借出成功后
         语音念给本人听 + 屏幕大字显示 + 可打印一张「借条」交给他带走
         （自助机接小票打印机即可自动出纸条；没打印机也不影响屏幕显示）；
      ② 他本人下次来刷卡（借或还任意一件）：当场提醒他名下还有哪些设备
         快到期 / 已逾期 —— 人就在机器前，说的正是他借走的东西，最有效；
      ③ 到期名单 → 「生成催还消息」：按借用人分组，措辞是给本人看的
         （"你借的「示波器」请于 10-30 18:00 前归还"），一键复制后可直接
         粘贴到班级群 / 私聊 / 短信发出去；用户管理里可填手机号便于联系；
      ④ 主控台顶部横幅只是给值班的人看「该去催了」，是辅助，不是主要手段。
      语音用 Windows 自带朗读引擎，不联网；没装中文语音包时自动跳过、不影响其它功能。
      用户表新增 phone（手机号）字段，老库会自动补列，无需手工改表。
  6.14 自动发邮件提醒（送到借用同学的邮箱，最可靠的"到人"方式）
      语音和横幅只能提醒站在机器前的人；同学把设备借走后就看不到了。
      配好一次 SMTP（QQ / 163 / 学校邮箱都行）后全程自动：
      · 借出成功即发「借用确认信」——信里写明设备与应归还时间，等于一张不会丢的电子借条；
      · 到期 / 逾期自动发「催还信」——一人一封（名下多件合并），不刷屏；
        同一台设备按提醒间隔最多一小时一封，不会反复骚扰；
      · 没填邮箱的同学自动跳过，不影响借还；没配 SMTP 或没网也只是发不出去。
      设置位置：系统设置 → ⑫ 自动邮件提醒（先点「发送测试邮件」验证，收到信再启用）。
      安全：填的不是邮箱登录密码，而是邮箱里生成的 SMTP 授权码；
      授权码用 Windows DPAPI 加密后存库，数据库文件被拷走也解不开。
      用户管理里新增「邮箱」字段（老库自动补列，无需手工改表）。
  6.12 自助终端模式（老师改进 #3，像闸机一样自己跑）
      系统设置 → ⑩ 自助终端：全屏无边框、触控大按钮、空闲 N 秒自动回主控台、
      关闭需 Ctrl+Alt+Q 或确认（防止被学生随手关掉）、屏幕常亮不熄屏、
      可选开机自动启动（断电来电后自动恢复可刷卡状态）。数据全在本机 SQLite，
      不依赖网络。
  6.13 校园卡适配（老师改进 #2：为什么现在刷不了校园卡）
      原因：现在的 UHF 读写器是 860~960MHz 超高频，读设备标签用的；
      校园卡是 13.56MHz（Mifare/CPU 卡），频率、天线、协议都不同，
      就像收音机收不到 WiFi —— 物理上读不到，不是程序坏了。
      解决：花几十元买一个 USB 免驱的 13.56MHz 读卡器（PC/SC 读卡器，
      如 ACR122U 或各品牌校园卡读卡器），插上后系统自动识别：
      「系统设置 → ⑪ 校园卡适配」里可看到读卡器列表、放卡测试读号；
      读到校园卡卡号(UID)后在「用户管理 → 刷卡建人」绑定给同学，
      以后刷校园卡就能识别身份完成借还，设备标签照旧用 UHF 读写器，互不干扰。
  7. 一键备份/恢复：启动自动备份（默认保留 10 份）+ 手动立即备份 + 从备份列表一键恢复，
     恢复前会再自动备份当前库（before_restore），不会丢数据。

二、程序简介
----------------------------------------------------------------
LabBorrow 是一套基于 UHF RFID 的实验室设备借还登记程序。把贴有
RFID 标签的设备靠近读写器，程序自动识别 EPC：

  · 设备在库  -> 刷卡弹出「借出登记」，填写借用人即可借出（或刷学生卡自动填）；
  · 再次刷卡  -> 一键归还，自动计算本次借用时长，逾期会标注；
  · 陌生标签  -> 友好提示，可在「设备管理」中登记为新设备。

程序用 C# / WinForms 编写，数据存放在本地 SQLite 数据库，无需
安装服务端，免安装、绿色运行。

三、运行环境
----------------------------------------------------------------
  · 操作系统：Windows 7 / 10 / 11（32 位或 64 位均可）
  · 运行库  ：.NET Framework 4.0 或更高版本（Win10/11 已自带 4.8）
  · 硬件    ：KL9007R 系列 UHF 读写器，USB 虚拟串口，波特率 57600
  · 提示    ：没有读写器也能运行，可查看设备台账、借还记录、用户与统计报表，
              只是无法刷卡登记。

四、快速开始
----------------------------------------------------------------
  1) 解压本压缩包。推荐解压到桌面以外的目录（例如 C:\LabBorrow），
     这样不会有下面第 2 步的完整性问题。
  2) 【若解压到「桌面」，务必先做这一步】
     双击运行  fix_integrity.bat   （只需运行一次）
     说明：Windows 的桌面目录可能带「低完整性(Low)」标签，解压出来
     的 LabBorrow.exe 会继承该标签并以低完整性级别运行，此时它只能
     读取数据库、无法写入 —— 表现为新增/编辑/删除设备、刷卡借还、
     删除记录全部报 "attempt to write a readonly database"。运行本
     脚本会把程序目录的完整性级别改回 Medium（正常级别）后即恢复。
  3) 双击运行  restore_database.bat
     把随包的数据库恢复到程序读取的位置：
         %LOCALAPPDATA%\LabBorrow\labborrow.db
     如果目标位置已有数据库，脚本会先自动备份（labborrow.db.bak，
     多次运行依次为 .bak1、.bak2…），绝不会删除原有数据。
     （只想用全新空库的话，可跳过这一步，程序首次运行会自建空库。）
  4) 双击运行  LabBorrow.exe
  5) 连接 KL9007R 读写器到电脑，点击右上角「连接读卡器」
     （程序启动时也会自动尝试连接一次）。
     连接成功后右上角会显示当前射频功率，例如「地址 0xFF 功率 20 dBm」。
  6) 把设备标签贴近天线并停留约 1 秒（需连续读到 2 轮 + 滑动窗口内累计
     命中 3 次），即可刷卡借还。系统设置里可放宽/收紧这两个门槛。
  7) 建议进「系统设置」页按现场情况调整读卡距离与间隔规则（见第六节）。

  ※ 从旧版本升级：直接把新 exe 覆盖旧 exe 即可。程序启动时会自动为老数据库
     补列（devices.due_time、records.due_time / user_card / overdue）并新建
     users、audit_log 表，原有设备、流水、设置一个都不会丢。

五、界面功能（六个页面）
----------------------------------------------------------------
  1. 主控台
       实时显示读卡器连接状态与功率、最近一次刷卡结果、设备信息卡片，
       「在借看板」（在借数量 + 在借明细，逾期红色 / 临期黄色），
       今日借出/归还/当前外借/设备总数统计，以及实时事件列表
       （借出、归还、拦截、距离开启未确认、读卡器日志、音效播放链路都记在这里）。
       关键信息已按演示要求放大：设备名称 32 号、借出/归还结果 14 号、
       操作反馈（✓ 借出成功 等）16 号、借用人/应还时间 13 号加粗、
       统计数字 24 号、在借件数 28 号。
       所有文案都做了「按可用宽度铺满 + 过长显示省略号」处理，
       设备名再长也不会把卡片顶出滚动条（已由界面冒烟的压力测试自动校验）。
  2. 设备管理
       设备台账：EPC、名称、型号、分类、存放位置、状态、当前借用人、
       借出时间、备注。支持关键字搜索与按状态筛选，可新增/编辑/
       删除设备，也可直接刷标签自动填入 EPC。状态含
       idle（在库）/ borrowed（借出）/ maintenance（维修）/ retired（报废）。
  3. 借还记录
       借还流水：时间、操作（借出/归还）、状态（已归还/未归还/逾期未还）、
       设备、借用人、时长/分、应还时间、EPC、备注。支持按日期区间查询，
       可多选删除记录（只删流水，不改设备当前状态），可导出 CSV。
  4. 用户管理（借用人 / 学生卡）
       借用人台账：卡号(EPC)、姓名、学号/工号、班级/部门、角色、在借数量、
       备注、更新时间。可新增/编辑/删除，可点「读取卡号录入」直接刷学生卡
       建人（同一卡号不允许重复登记）。
  5. 统计报表
       区间指标卡（借出次数/归还次数/当前在借/逾期未还/平均借用小时/设备总数）
       + 借出归还趋势柱状图 + 设备借出排行 + 借用人借出排行 + 分类借出占比环形图，
       支持把报表导出为 CSV。
       视觉与交互：圆角卡片、渐变柱条、环形占比（中心显示合计），
       鼠标移到柱子/长条/扇区上会高亮并显示数值气泡。
  6. 系统设置
     ※ 每个分区的标题都可以点击，用来展开/收起该分区（标题前的 ▼/▶ 表示状态）。
       默认展开：① 读卡距离、② 刷卡间隔与防刷、⑦ 提示音效（这三项最常用）；
       默认收起：③ 借用期限、④ 借用人卡、⑤ 备份恢复、⑥ 刷卡审计。
       收起既能让页面更清爽，也能让切换更快（收起的控件不参与布局）。
      ① 读卡距离限制：距离档位下拉（15/18/22/26/30 dBm 或自定义、不修改，
         选档位会同时调整功率、连续命中确认、滑动窗口内累计命中次数）、
         射频功率、连续命中确认轮数、滑动窗口内累计命中次数、累计命中
         窗口时长、盘点间隔、同标签上报冷却；
         「应用到读卡器」把功率实时写入读卡器，「读取读卡器信息」查看版本/功率；
         「解除全部刷卡锁定」用于演示现场误触发防刷后一键恢复。
      「滑动窗口内累计命中」+「累计命中窗口时长」是新增的双层过滤，专门过滤
         远距离偶发读到：默认窗口 2.5s 内必须累计 3 次命中才算稳定。把窗口缩到
         1s/3 次时只有真正贴近的标签才能通过；设成 1/1 即关掉这层过滤。
       ② 刷卡间隔时限：全局最小间隔、借出→归还、归还→借出、异常统计窗口、
          窗口内同卡上限、窗口内全局上限、锁定时长。
       ③ 借用期限：默认借用天数、临期提醒提前小时数。
       ④ 借用人卡：双卡模式开关、借用人卡有效期。
       ⑤ 数据备份与恢复：启动自动备份开关、保留份数、立即备份、
          备份列表、恢复选中备份、打开备份目录 / 打开数据库位置。
       ⑥ 刷卡审计：最近的拦截记录（时间/类型/标签/原因），可刷新、可清空。
      ⑦ 刷卡提示音效（演示演示效果重点）：总开关、音量、最长播放秒数，
         并可为「借出成功 / 归还成功 / 刷卡被拦截 / 异常刷数据被锁定」
         分别指定音频文件（支持 mp3 / wav / wma / mid），每行都有
         「浏览…」和「试听」按钮，不必先保存就能当场听效果。
         路径留空则用内置合成音：借出=上行双音、归还=下行双音、
         拦截=低沉双音、异常=急促警报。
         演示建议：把「异常刷数据被锁定」设成
             D:\CloudMusic\电台节目\华语原声带 - Man！曼巴out.mp3
         同一标签在统计窗口内反复刷卡就会被判为恶意刷数据并锁定，
         随即播放该音效，老师一眼就能看到「防刷」生效。

         ※ 实现说明：Windows 自带的 MCI 接口打不开含中文 / 全角标点的路径
           （实测报 0x10A 无效文件），所以程序采用三级兜底：
             MCI → Windows Media Player COM → 内置合成音
           全部只用系统自带组件，不加任何 dll，播放走后台线程；
           万一都失败也只是没声音，绝不影响借还登记。
           每次播放会把实际走的链路写进主控台「实时事件」列表，便于排查。

         ● 导入音频最省事：把 mp3/wav 等音频文件【直接拖到】下面任意一行输入框里，
           会问你要不要复制一份到程序目录的 sounds 文件夹（推荐，原文件丢了音效还在），
           也可以点「浏览…」选择。支持 mp3 / wav / wma / m4a / aac / flac / ogg / mid。
         ● 不用把音频放到根目录：拖入导入时选「是」就会自动复制一份到 sounds 文件夹。
         ※ 没声音怎么排查（按这个顺序 30 秒定位）：
           1) 到设置 ② 区点「模拟一次异常锁定（演示音效）」按钮——
              不用真刷卡，点击立即播放异常音效，课堂上验证最方便。
              · 出声     → 音效链路正常；
              · 没出声   → 看下一步；
           2) 看「试听」按钮和主控台底部「实时事件」列表最后几行：
              · 出现「文件放不出来，已改用内置合成音」→ 音频文件路径无效
                或该文件正被其它播放软件独占占用（先关掉播放器再试）；
              · 出现「播放：Man！曼巴out.mp3」→ 播放器已启动，检查系统音量；
           3) 若启动时弹出「数据库只读」对话框或顶部有红色提示条：
              设置项全都保存不住（改了也是白改），点「立即修复」运行
              fix_integrity.bat，跑完后重启本程序（见第十三节）。

  业务规则
   · 刷卡（设备在库）  -> 登记借出，需选择/输入借用人（双卡模式下刷卡即借出）；

十二、常见问题
----------------------------------------------------------------
  Q: 刷标签没反应，或者要贴一会儿才认？
  A: 这是「连续命中确认」在起作用：标签需要在连续 2 轮盘点中都被读到（约
     0.5 秒），请把标签贴近天线并停留约 1 秒。想恢复“一贴就认”，把系统设置里
     的「连续命中确认」改成 1 即可（代价是远距离误刷概率回升）。

  Q: 事件列表出现「! 距离 未确认」？
  A: 说明该标签只被零星读到（离得太远 / 没对准天线 / 贴着金属遮挡），程序按
     距离限制把这次刷卡判为无效，没有产生借还记录 —— 这正是防止误刷的效果。
     需要更远也能刷，就把射频功率档位调大（例如 26 dBm），或把标签贴正。

  Q: 提示「该标签短时间内被反复刷卡，已临时锁定」？
  A: 触发了防刷规则（默认 60 秒内同一标签超过 8 次）。等锁定时间结束即可，
     或在「系统设置」页点「解除全部刷卡锁定」，也可以把阈值调大。

  Q: 借出后标签一直放在读卡器上，会不会被自动归还？
  A: 不会。同一标签在同一位置只会上报一次（边沿触发），即使拿开再放回，也还
     受「借出→归还最短间隔」（默认 10 秒）保护。

  Q: 老数据库 / 老数据能直接用吗？
  A: 能。程序启动时会自动补列建表（devices.due_time、records.due_time /
     user_card / overdue，新建 users、audit_log），原有数据不动。
     随包数据库已按新结构升级，也可运行 restore_database.bat 恢复。

  Q: 学生刷卡借出怎么配置？
  A: 两步：①「用户管理」页用「读取卡号录入」把学生卡与姓名登记好；
     ②「系统设置」页勾选「借用人卡双卡模式」并保存。
     此后学生先刷自己的卡，再刷设备标签即可借出（8 秒内有效，可调）。

  Q: 数据怎么备份、误删了怎么找回？
  A: 程序每次启动会自动备份，也可在「系统设置」页随时「立即备份」。误删后在
     该页的备份列表里选中相应备份点「恢复选中备份」，恢复前程序还会把当前库
     另存一份 before_restore 安全备份。

  Q: 想换一台电脑继续用原来的数据？
  A: 把整个 LabBorrow_Release 目录拷过去，先运行 restore_database.bat，
     再运行 LabBorrow.exe（或者带上 backups 目录，用备份恢复）。

  Q: 增删改设备、刷卡借还都报 "attempt to write a readonly database"？
  A: 见第十三节：程序被解压到了带 Low 完整性标签的目录（通常是桌面）。
     运行 fix_integrity.bat，或把程序搬到桌面以外的目录，然后重开程序。

  Q: 提示「未找到可用读卡器」或「读卡器无响应」？
  A: 确认 KL9007R 已通过 USB 连接、驱动正常（设备管理器能看到虚拟
     串口），再点「连接读卡器」。命令行可用 mode 查看串口列表。
     （若程序正以低完整性运行，也可能影响设备访问，建议先按第十三节修复。）

  Q: 提示「设置射频功率失败」？
  A: 说明该读卡器型号不支持 SetPowerDbm 或当时通信异常。程序会沿用读卡器
     当前功率继续工作（不会崩溃）；可点「读取读卡器信息」确认实际功率。
     此时「连续命中确认」仍然提供软件层面的误刷保护。

  Q: 提示缺少 .NET Framework？
  A: 安装 .NET Framework 4.0 或更高版本（推荐 4.8）后重试。

十三、完美复现与排查记录（低完整性级别问题，沿用第二版结论）
----------------------------------------------------------------
  问题现象：解压后运行 LabBorrow.exe，程序能打开、设备列表和历史
  记录都能看到，但任何写操作（新增/编辑/删除设备、刷卡借还、删除
  记录）都弹出错误：

      System.Data.SQLite.SQLiteException (0x87AF1779):
      attempt to write a readonly database

  排查结论：这不是数据库文件或目录权限的问题，而是 Windows 的
  「完整性级别(Integrity Level)」机制：

    1. C:\Users\L\Desktop 目录带有可继承的强制标签
       「Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)」
       （NW = no-write-up，禁止向上写）；
    2. 桌面上的所有文件/文件夹都继承该标签，包括解压出来的
       LabBorrow.exe；
    3. Windows 启动一个带 Low 标签的 exe 时，会把进程的完整性级别
       也定为 Low 级；低完整性进程按规则「可读中等完整性对象、
       不可写中等完整性对象」；
    4. 数据库在 %LOCALAPPDATA%\LabBorrow\ 下，属于中等完整性，
       所以能读、不能写 —— 报错信息正是 readonly。

  验证方式：把同一个 whoami.exe 放在 C:\Windows\System32（无标签）
  和桌面上（继承 Low），分别运行 whoami /groups：
       System32  -> Mandatory Label\Medium Mandatory Level
       桌面上    -> Mandatory Label\Low Mandatory Level

  修复方式（任选其一）：
    · 把程序解压到桌面以外的目录，例如 C:\LabBorrow（推荐，一劳永逸）；
    · 或运行本包内的 fix_integrity.bat，把程序目录改回 Medium；
    · 或手工执行：
        icacls "<程序目录>" /setintegritylevel (OI)(CI)Medium /T
  注意：脚本(.bat)本身不受该标签影响（cmd.exe 仍以 Medium 运行），
  所以 fix_integrity.bat 即使在低完整性目录里也能正常修复。

十四、设计说明：为什么距离限制用“功率 + 命中确认”
----------------------------------------------------------------
  · 本项目使用的 SDK（UHFReader18CSharp.dll，RRU1861/KL9007R 系列）对外
    提供的接口是 AutoOpenComPort / OpenComPort / Inventory_G2 / Getpower /
    SetPowerDbm / GetReaderInformation 等，**没有提供 RSSI（信号强度）接口**。
    因此无法用“信号强度阈值”判断距离。
  · 硬件层面：UHF 无源标签的读取距离与读写器发射功率近似成正比，把功率从
    30 dBm 降到 18~22 dBm 可把有效距离从数米压到几十厘米，这是最直接、
    最可靠的距离限制手段（对应 SetPowerDbm）。
  · 软件层面：距离边缘的标签只会被“偶尔读到”，而贴近天线的标签会在每一轮
    盘点中都被读到。TagGate 用“连续命中确认 + 漏盘容忍 + 边沿触发”把这
    差别变成可判定的规则，既能挡掉远距离偶发误读，又不会把正常刷卡挡掉
    （正常贴近停留约 1 秒即可满足）。
  · 两者配合，再加上刷卡间隔与防刷锁定、审计留痕，就构成了“不误刷、也
    不能恶意刷”的完整闭环。
